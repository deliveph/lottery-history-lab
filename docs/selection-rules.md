# 固定10元分散单式选号规则

生效日期：2026-09-10。用户已确认后续默认采用本规则，取代综合起卦作为默认方案。

## 目标与预算

- 每种彩票每期5注基本投注，每注1倍、2元，合计10元；两种彩票都参与时合计20元。
- 优先考虑至少一注达到实际奖级的机会，分别统计中奖、回本和盈利。
- 默认使用分散单式，不自动改成复式、胆拖、倍投或大乐透追加投注。
- 不因连续未中增加预算。不能保证中奖，也不能保证回本。

## 号码约束

| 游戏 | 单注要求 | 5注组合要求 |
|---|---|---|
| 双色球 | 红球01—33选6个，蓝球01—16选1个 | 各组红球互不重叠，共30个不同红球；5个蓝球互不相同 |
| 大乐透 | 前区01—35选5个，后区01—12选2个 | 5注完整号码互不相同；默认前区互不重叠，共25个不同前区号，后区互不重叠，共10个不同后区号、5个不同号码对 |

每注同一区内不得重复，按从小到大、两位数字展示。大乐透上述结构是当前采用的
分散方案，尚未证明它是同预算下任意奖概率的最优结构。后续比较应按完整号码对
和实际奖级计算，不能仅用覆盖球数认定更优。

历史热冷、生日、方位、财位和起卦不作为预测优势。只有用户明确要求起卦时才使用
该娱乐映射，并仍须满足本页的预算和号码约束。

## 使用已有程序

当前 CLI 不带参数仍默认使用 `weighted`；执行本规则必须显式指定 `coverage`。
已有覆盖模式可生成上述分散结构，例如：

```powershell
python -m lottery_lab run --mode coverage --count 5 --seed 20260910
```

示例种子仅用于复现，不代表推荐期次或预测优势。实际运行时记录使用的种子，
不要为了得到看起来更顺眼的结果反复换种子。`run` 会刷新历史缓存，但不会自动
归档候选号码到对话日志；执行者仍须按下面流程保存输出并检查约束。

## 开奖前与开奖后记录

1. 生成前刷新官方历史，核对目标日期、游戏和期号；不得把已开奖期次当作预测目标。
2. 检查注数、金额、范围、区内及跨注重复情况；不符合约束的输出不得直接交付。
3. 开奖前在北京时间对应的每日日志中保存目标期次、生成时间、模式、种子、
   数据截止期和完整5注号码；保留已发布版本，不能开奖后覆盖或改写原号码。
4. 2026-09-10双色球2026105期沿用9月9日已发布且符合约束的5注，不重新选号。
5. 开奖后刷新官方数据，按当期有效规则、奖金与特别奖条件逐注核对，未中也完整记录。
6. 分别记录：中奖注数、总奖金、基本投注成本、净额，以及是否中奖、是否回本
   （奖金不低于成本）、是否盈利（奖金高于成本）。未确认实际购买时注明“按全部购买测算”。
7. 覆盖球数仅为辅助统计，不能把跨注命中拼成一注中奖，不能把覆盖高解释为预测准确。

本规则规范后续选号与记录流程；当前没有自动核奖、自动保存候选号码或保中功能。
